== Overview

*flowlab* is an *unsampled network-flow observability appliance*.  Its single
purpose: understand and verify — with *exact, per-destination byte accounting over
time* — what this MacBook consumes toward the internet over its uplink (the Android
hotspot), so surprises are explainable and future carrier bills match reality.
*Sampling is banned* (sampled flows only estimate bytes).

The system is a two-stage pipeline:

* a *probe* on the bare-metal Mac captures the physical Wi-Fi and exports NetFlow v9;
* a *collector* (Akvorado, split across two Incus instances) ingests, enriches and
  stores every flow, and serves a console.

It is a *tenant* of two neighbours in the seedmatic lab: *ndh* provisions the
network it attaches to (the `bare-br` segment) and owns the *network catalog* it
reads for attribution; *rke2lab* contributes its cluster spans to that catalog.

*Why the probe MUST run on bare metal:* the MacBook's own unicast to the gateway
only exists on the host's *physical* `en0`.  A bridged guest never sees it (switched
L2), so a VM-hosted probe would miss the very traffic being accounted.

== C4 · Level 2 — Containers

The pipeline is split across *two NixOS Incus instances*, both attached to ndh's
`bare-br` segment, along a *failure-domain* line rather than by workload weight:

* *`nnh-inlet` — the self-contained ingest edge* — runs the orchestrator + inlet
  *and* Kafka.  Co-locating all three means it can receive the probe's NetFlow,
  buffer to a *local* Kafka, and serve config to every daemon *without* the store
  node.  An `nnh-outlet` outage therefore loses *no* flows: the inlet keeps
  buffering and the outlet drains the backlog when it returns.
* *`nnh-outlet` — the store* — runs the outlet + console and the one irreplaceable
  backend, *ClickHouse* (the flow history), plus Redis and the GeoIP fetch.
  Everything on the inlet is reconstructible (config is baked in Nix, Kafka is a
  ≤1-day buffer); ClickHouse is not — so it, and only it, gets the persistent volumes.

They address each other *by name* over bare-br.

[cols="1,3"]
|===
| Container | Role

| *pmacctd (nnh-probe)* | libpcap capture of `en0`, unsampled; exports NetFlow v9 to the inlet BY NAME.  Root LaunchDaemon on the vz Mac (outside the darwin fleet), rendered at deploy time.
| *akvorado orchestrator* (nnh-inlet) | holds the whole pipeline config (one `akvorado.yaml`), serves it to every daemon; provisions the Kafka topic (local) + ClickHouse schema (remote → nnh-outlet).
| *akvorado inlet* (nnh-inlet) | receives NetFlow on `:2055`, produces raw flows to the local Kafka.  Fetches its config from the local orchestrator.
| *Kafka* (nnh-inlet) | the transient flow buffer (KRaft, ≤1-day retention); ephemeral by design — sits on the inlet so ingest survives a store outage.
| *akvorado outlet* (nnh-outlet) | consumes Kafka (remote), enriches (attribution + GeoIP) and writes rows to ClickHouse (local).
| *akvorado console* (nnh-outlet) | the Visualize UI, on `:80`; reads ClickHouse, caches in Redis (both local).
| *ClickHouse / Redis* (nnh-outlet) | reused nixpkgs backends; native systemd, *no Docker/podman* (the netavark UDP hostport DNAT was unreliable — see CLAUDE.md).  ClickHouse binds bare-br (`listen_host=0.0.0.0`) so the remote orchestrator can provision it.
|===

NOTE: All the pipeline configuration (the `:2055` listener, the Kafka target, the
sampling rate, the attribution networks, the console `:80`, …) lives in the
*orchestrator's* config on `nnh-inlet`.  `nnh-outlet` carries none — the outlet and
console just run `akvorado {outlet,console} http://nnh-inlet.nikopol:8080` and fetch
everything.  The split is a *failure domain*, not a config boundary: the ingest edge
holds the config authority so it needs nothing from the store to run.

== Flow — the journey of one flow

[mermaid]
....
sequenceDiagram
  autonumber
  participant EN as en0 (bare metal)
  participant PM as pmacctd
  participant IN as inlet
  participant KA as Kafka
  participant OU as outlet
  participant CH as ClickHouse
  participant UI as console

  EN->>PM: packets (both directions, promiscuous)
  Note over PM: aggregate by 5-tuple, sampling_rate=1 (exact bytes)
  PM->>IN: NetFlow v9 to nnh-inlet.nikopol port 2055 (after ~60s)
  Note over IN: no-direction map stamps InIf=OutIf=0 — enricher-ifindex0 patch resolves via the catch-all exporter
  IN->>KA: produce to topic flows
  KA->>OU: consume
  Note over OU: enrich — SrcAS/DstAS + NetName from ndh catalog, GeoIP for public dests
  OU->>CH: write enriched row
  UI->>CH: Visualize (internet-only, ranked by total bytes)
....

CAUTION: The macOS capture MUST use a *single interfaces.map entry with NO
`direction=`* — any direction makes libpcap inbound-only on macOS (uploads lost).
The trade-off (flows stamped `InIf=OutIf=0`) is handled on the collector by our
`pkgs/akvorado-enricher-ifindex0.patch`, which resolves ifindex-0 via the `::/0`
static exporter instead of dropping.  See CLAUDE.md for the full learning.

== Attribution & the catalog federation

flowlab labels *"your side"* of every flow — a `NetName` + AS — from *ndh's network
catalog* (the single source of truth), and public destinations get their real AS
from GeoIP.  No addressing or AS mapping is hardcoded.

[mermaid]
....

  subgraph eval [Eval / flake layer — data flows UP]
    direction LR
    NNHb["nnh (flowlab)\nlib.networkBlueprint\n(its 2 bare-br hosts, ip=null)"]:::wl
    RKEb["rke2lab\nlib.networkBlueprint\n(cluster spans)"]:::wl
    CAT["ndh catalog\nnetplan.segments {cidr,name,asn} + asns"]:::data
    RKEb -->|"union"| CAT
    NNHb -->|"union"| CAT
  end
  CAT -.->|"consumed at eval → outlet.networks + clickhouse.asns"| OUT["outlet enrichment\n(most-specific-prefix-wins)"]:::wl
  GEO[("GeoIP mirrors\nASN + City (tokenless)")]:::infra
  GEO -.->|"public dests → real AS + geo"| OUT

  classDef infra fill:#bfdbfe,stroke:#1e40af,color:#000;

* *Consume* — `ndh.catalog.netplan.segments` become `outlet.networks` (prefix →
  `{name, asn}`, most-specific-wins) and `ndh.catalog.netplan.asns` becomes the
  `asns` ClickHouse dictionary.  Private ASes name your side (e.g. `65000 home`,
  `65010 rke2-cluster`, `65020 gateway`); per-host `/32`s refine the `NetName`.
* *Contribute* — flowlab exposes `lib.networkBlueprint` declaring the two collector
  hosts (`nnh-inlet`/`nnh-outlet`, `ip = null` — resolved via DNS), which ndh unions
  into the catalog.
* *No flake cycle* — ndh must input nnh (to read the blueprint) while nnh inputs ndh
  (to read the catalog).  The mutual dependency is broken with reciprocal
  `inputs.<other>.inputs.<self>.follows = ""` (empty follows = the ROOT flake, a
  fixpoint).  Invariant: the blueprint stays *self-contained* (never reads the
  catalog) or the value cycle returns.  See the hub note
  `flake-mutual-dependency-follows-root`.

== Reachability & naming

Both instances are plain *DHCP tenants* of `bare-br` (ndh-provisioned:
`172.16.6.0/25`, `dns.domain=nikopol`, dnsmasq/gateway `172.16.6.1`).  Everything is
addressed *by name* — no static IPs.

[mermaid]
....

  VZ["vz.nikopol en0 alias\n172.16.6.253/30 (ndh baremetal-link)"]:::ext

Three gates must all hold (any one missing → resolves-but-unreachable, or vice
versa):

. *Route* — nikopol-nixos advertises `172.16.6.0/24` into the tailnet; peers reach
  the instances via the subnet router.  The vz Mac reaches bare-br via the
  `172.16.6.253/30` link (ndh's `baremetal-link` daemon).
. *Name* — `bare-br` dnsmasq serves the `.nikopol` zone.  With `dns.mode=dynamic`
  the record follows the guest's DHCP hostname (`networking.hostName` = `nnh-inlet`/
  `nnh-outlet`), so the Incus instance names can stay unprefixed (`inlet`/`outlet`).
. *Resolver (macOS)* — the vz Mac needs a scoped `/etc/resolver/nikopol → 172.16.6.1`
  (ndh's `baremetal-resolvers` darwin module); a flat resolver never routes a
  split-horizon domain.

CAUTION: `bare-br` runs `ipv4.nat=false` — instances have *no internet egress*
(known ndh open item, fixed by a selective masquerade on the subnet router).  Impact
on flowlab: only the periodic GeoIP refresh; the databases persist on a volume, so
current enrichment is unaffected.

== Deployment

`nix run .#collector-deploy` (a darwin operator tool driving the `nikopol-nixos`
Incus remote) brings the whole appliance up in the `nnh` Incus project:

. builds both aarch64-linux images (via the remote builder);
. ensures the project, the outlet's persistent volumes, and both profiles;
. imports each image and *launches* the instances — or `incus rebuild`s them from a
  new image, which *keeps the volumes* (ClickHouse history, GeoIP DBs, the tailnet
  identity survive updates);
. chains the probe deploy (`nnh-probe-deploy`) last — the inlet must be listening
  before the probe starts exporting (UDP is fire-and-forget).

[cols="1,3"]
|===
| Persistent volume (nnh-outlet) | Survives rebuild

| `data` | ClickHouse flow history
| `akvorado` | GeoIP mmdbs + console.sqlite (saved filters/users)
| `tailscale` | tailnet node identity (`nikopol-netflow`)
|===

== Reading the flows (console)

The console is at `http://nnh-outlet.nikopol`, *Visualize* tab.

*The orientation caveat.* The probe is a *single exporter with no NetFlow direction*
(the no-direction `interfaces.map`), so every flow lands `InIfBoundary=external,
OutIfBoundary=undefined` — akvorado *cannot* tell "in" from "out" on its own.  Worse,
addressing is network-dependent: on the hotspot the Mac gets a *carrier* IP (a real
public AS), not our private `65000`.  So *direction is decided by which endpoint is
private*, address-based — never by AS (that breaks off the home LAN) and never by
boundary (undefined here).  The four saved filters encode exactly that:

[cols="1,3"]
|===
| Saved filter | Meaning

| *Outbound — you → internet* | `SrcAddr` private AND `DstAddr` public (uploads)
| *Inbound — internet → you* | `SrcAddr` public AND `DstAddr` private (downloads)
| *Internet only* | either endpoint public (both senses, LAN chatter excluded)
| *LAN internal only* | both endpoints private (no internet)
|===

*Attribution — who is who.* "Your side" is named from the ndh catalog: `SrcNetName`/
`DstNetName` carry the per-host name (`nikopol`, `vz.bioskop`, …) and `SrcAS`/`DstAS`
the private AS (`65000 home`, `65010 rke2-cluster`, `65020 gateway`).  The internet
side gets its real AS *name* from the `asns` dictionary (akvorado's built-in table:
`13335 Cloudflare`, `36459 GitHub`, `14618 Amazon`, `5410 Bouygues Telecom`, …).

*Dimensions — the fix for "I can't tell my sources apart".* The default `SrcAS→DstAS`
collapses every internal host into the one AS `65000`.  Pick instead:

* `SrcNetName` — *which of my hosts* (per-host, readable).  The pre-configured default.
* `DstAS` / `Dst2ndAS` — *toward which network* (named).
* `DstAddr` / `DstPort` — drill into a specific destination / service.

*Graph modes — when to use which:*

[cols="1,3"]
|===
| Mode | Use it for

| *stacked* (default) | *bytes over time* — the core flowlab question ("what ate my GB, and when").  Each dimension value is a band; height = bytes in each time bucket.
| *stacked 100%* | the same, normalized to share-of-total per bucket (proportions, not volume).
| *lines* | one line per series — comparing trends/spikes without the stacking.
| *grid* | small-multiples: one mini time-chart per series, side by side.
| *sankey* | *who → whom, as totals over the whole window* (no time axis).  Left column = one dimension, right = the next, band width = bytes.  With *Outbound* + dimensions `SrcNetName, DstAS` it draws `nikopol → GitHub`, `nikopol → Amazon` — the clearest "where did my upload go".  Add a 3rd dimension (e.g. `DstAddr`) for a third column.
|===

TIP: Sankey needs *≥2 dimensions* and shows a *snapshot total*, so pair it with a
direction filter (Outbound/Inbound) — mixing both senses makes the bands ambiguous
(your side would appear on both the left and the right).  For "over time" always use
*stacked*.

The pre-configured default lands on *Outbound, stacked, `SrcNetName → DstAS`, last 24 h*
— your hosts and where their uploads went.  Flip to the *Inbound* saved filter for the
download side (usually the bigger number on a metered uplink).
